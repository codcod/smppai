[#client]
= The client

`SMPPClient` is an ESME (External Short Messaging Entity): it connects
outward to an SMSC, binds, and then sends or receives.

[#high-level-api]
== High-level API

For most applications, `smpp.connect()` is all you need. It connects and
binds in one step and hands back a `Client`:

[source,python]
----
import smpp

async with smpp.connect("localhost", 2775, "my_client", "my_pass") as client:
    result = await client.send("+306900000000", "Γειά σου!", sender="ACME", receipt=True)
    print(result.message_ids, result.parts, result.data_coding)

    async for msg in client.messages():
        if msg.is_receipt:
            print("receipt", msg.receipt.id, msg.receipt.state)
        else:
            print("from", msg.sender.addr, ":", msg.text)
----

`connect(host, port, system_id, password, *, bind="trx", **client_kwargs)`::
Binds as transceiver by default; pass `bind="tx"` or `bind="rx"` for
transmitter or receiver. Any other value raises `ValueError` before a socket
is opened. Extra keyword arguments go to the `SMPPClient` constructor.
Leaving the block unbinds and disconnects.

`send(to, text, *, sender="", receipt=False, timeout=None) -> SendResult`::
Encodes as GSM-7 (`DataCoding.DEFAULT`) when the text fits the GSM alphabet,
otherwise as UCS2, and splits long text into concatenated parts via
`submit_multipart`. `receipt=True` requests a success/failure delivery
receipt. The `SendResult` holds `message_ids` (one per part), `parts` and
`data_coding`. Errors propagate unchanged from `submit_multipart`; a failure
mid-sequence carries `.sent_message_ids`.

`messages()`::
An async iterator of inbound `Message` objects. Only one consumer may iterate
at a time; a second concurrent `messages()` raises `RuntimeError`. Messages
are queued from the moment `connect()` binds; up to 1000 unread messages are
buffered, and beyond that the oldest are dropped with a warning. A
concatenated message whose parts stay incomplete for 5 minutes is discarded.
Iteration ends when the `connect()` block exits, and raises the underlying
error if the connection drops. To iterate again right after a `break`, wrap
the first loop in `contextlib.aclosing(c.messages())` so it is closed at once.

`Message`::
`sender` and `to` (`Address`), `text` (decoded per `data_coding`, or `None`
when it cannot be decoded, e.g. binary data), `receipt` (`DeliveryReceipt` or
`None`), `is_receipt`, and the raw `pdu`. Concatenated parts are reassembled
into one `Message` before it is yielded; its `pdu` is the last part received.
An inbound `data_sm` is yielded too: its `text` comes from `message_payload`,
it is never reassembled, and its `pdu` is the `DataSm`.

`DeliveryReceipt`::
`id`, `state` (`MessageState`), `stat`, `err`, `submit_date`, `done_date` and
`text`, parsed from the SMPP Appendix B receipt text. The
`receipted_message_id` and `message_state` TLVs take precedence over the text
when present and well-formed. A `data_sm` receipt has no receipt text, so
only `id` and `state` (from those TLVs) are set.

`Address.parse(s)`::
`"+306900000000"` becomes international/ISDN (the `+` is dropped), plain
digits become unknown/unknown, and anything else (e.g. `"ACME"`) becomes an
alphanumeric sender. Spaces and `-` are ignored in numbers, so
`"+30 690 000 0000"` is international too; only ASCII digits count as a
number. `send` accepts a `str` or an `Address` for `to` and
`sender`.

`client.raw`::
The underlying `SMPPClient`, for anything the high-level API does not cover
(`query_sm`, `cancel_sm`, raw `submit_sm` fields, ...). Its `on_deliver_sm`,
`on_data_sm` and `on_connection_lost` handlers belong to `messages()`;
replacing any of them stops `messages()` from receiving.

The rest of this chapter documents that low-level `SMPPClient`.

== Constructing a client

[source,python]
----
from smpp import SMPPClient, NpiType, TonType

client = SMPPClient(
    host="localhost",
    port=2775,
    system_id="my_client",        # <= 15 chars
    password="my_pass",           # <= 8 chars
    system_type="SMS_APP",        # <= 12 chars
    interface_version=0x34,
    addr_ton=TonType.UNKNOWN,
    addr_npi=NpiType.UNKNOWN,
    address_range="",
    bind_timeout=30.0,
    enquire_link_interval=30.0,   # automatic keepalive; 0 disables it
    response_timeout=10.0,        # default timeout for bind/submit/enquire
)
----

`system_id`, `password`, `system_type` and `address_range` are validated
against SMPP v3.4's field limits (16/9/13/41 bytes respectively, each
including the C-string terminator) when you bind.

After a successful bind, `client.sc_interface_version` holds the version the
SMSC reported (`sc_interface_version` TLV), or `None` if it reported none;
it resets to `None` on unbind or disconnect. It is informational only.

== Connecting and binding

[source,python]
----
await client.connect()

await client.bind_transmitter()   # can only submit_sm
await client.bind_receiver()      # can only receive deliver_sm
await client.bind_transceiver()   # both
----

Or use the client as an async context manager, which calls `connect()` on
entry and `disconnect()` (which unbinds first, if bound) on exit — see
<<quickstart,Quick Start>>.

State is exposed through properties:

[cols="1,3"]
|===
| Property | Meaning

| `is_connected`
| TCP connection to the SMSC is open.

| `is_bound`
| Connected *and* a bind succeeded.

| `bind_type`
| `BindType.TRANSMITTER` / `RECEIVER` / `TRANSCEIVER`, or `None`.

| `connection_state`
| The underlying `ConnectionState` (`CLOSED`, `CONNECTING`, `CONNECTED`, `BOUND`, ...).
|===

Two coroutines poll state instead of raising, for callers that would rather
wait than handle an exception:

* `await client.wait_for_connection(timeout=None) -> bool`
* `await client.wait_for_bind(timeout=None) -> bool`

Both return `False` on timeout instead of raising.

== Sending a message

[source,python]
----
message_id = await client.submit_sm(
    source_addr="1234",
    destination_addr="5678",
    short_message="Hello World!",
    source_addr_ton=TonType.INTERNATIONAL,
    source_addr_npi=NpiType.ISDN,
    dest_addr_ton=TonType.INTERNATIONAL,
    dest_addr_npi=NpiType.ISDN,
    registered_delivery=RegisteredDelivery.SUCCESS_FAILURE,  # request a delivery receipt
    data_coding=DataCoding.DEFAULT,
    timeout=10.0,   # overrides response_timeout for this call
)
----

`submit_sm` requires a transmitter or transceiver bind; it raises
`SMPPInvalidStateException` otherwise. `short_message` is a `str` and is
encoded according to `data_coding` — see <<data-coding,Data coding
schemes>> for the full mapping and what happens when text doesn't fit the
chosen coding. The call returns the SMSC-assigned message ID as a string.

For messages longer than a single SMS segment, use
`client.submit_multipart(...)` instead of `submit_sm` — same arguments,
plus `data_coding` and `registered_delivery` are applied to every part:

[source,python]
----
message_ids = await client.submit_multipart(
    source_addr="1234",
    destination_addr="5678",
    message=long_text,
    data_coding=DataCoding.DEFAULT,
)
----

It splits the message with `smpp.gsm.make_parts()`, sends one `submit_sm`
per part as a UDH-concatenated SMS, and returns their `message_id`s in part
order (a message that fits one segment returns a list of length 1). Parts
are sent sequentially and stop at the first failure; the raised
`SMPPMessageException` carries `.sent_message_ids`, the ids already
accepted, so the caller can cancel them with `cancel_sm(message_id, ...)`
(see <<managing-submitted-messages,Managing submitted messages>>) — there
is no automatic rollback or retry. `submit_sm` itself still raises
`SMPPMessageException` above `MAX_SHORT_MESSAGE_LENGTH` (254 octets) and
never splits on its own. See <<gsm,GSM encoding, segmentation and UDH>> for
the encoding and budget details.

To send as `data_sm` instead, use `client.data_sm(...)`. It takes the same
address, `esm_class`, `registered_delivery` and `data_coding` arguments as
`submit_sm`, and `message` may be a `str` (encoded per `data_coding`) or
`bytes`, `bytearray` or `memoryview` (sent as-is). The content travels in the
`message_payload` TLV, so there is no 254-octet limit and no splitting. The
whole PDU must still fit in 65,536 bytes, so the payload can be at most about
65,500 octets (less the lengths of the addresses and `service_type`); anything
larger raises `SMPPMessageException` before it is sent:

[source,python]
----
message_id = await client.data_sm("1234", "5678", long_text)
message_id = await client.data_sm("1234", "5678", b"\x00\x01...", data_coding=DataCoding.OCTET_UNSPECIFIED_2)
----

It needs a transmitter or transceiver bind, and it raises the same
exceptions as `submit_sm`.

[#managing-submitted-messages]
== Managing submitted messages

Once a message is submitted, its SMSC-assigned `message_id` can be used to
query its status, cancel it, or replace its text. All three require a
transmitter or transceiver bind, like `submit_sm`, and raise
`SMPPInvalidStateException` otherwise. A non-`ESME_ROK` response raises
`SMPPMessageException` with `.command_status` set to the SMSC's status code.

[source,python]
----
response = await client.query_sm(message_id, source_addr="1234")
response.message_state  # a smpp.MessageState value
response.final_date
response.error_code

await client.cancel_sm(message_id, source_addr="1234", destination_addr="5678")

await client.replace_sm(
    message_id,
    "Updated text",
    source_addr="1234",
    data_coding=DataCoding.DEFAULT,
)
----

`query_sm` returns the `QuerySmResp` PDU, with typed `message_state`,
`final_date` and `error_code` fields. `cancel_sm` and `replace_sm` return
`None` on success.

`replace_sm` has no `data_coding` field of its own — the SMSC applies the
original message's data_coding when redisplaying the replacement text, so
pass the same `data_coding` the message was originally submitted with. The
encoded replacement text is capped at `MAX_SHORT_MESSAGE_LENGTH` (254
octets), like `submit_sm`.

== Testing the link

[source,python]
----
ok = await client.enquire_link(timeout=5.0)  # True/False, never raises
----

An `enquire_link_interval` was already set on the client's connection at
construction time, so this is only needed for an explicit, synchronous
liveness check; the periodic keepalive runs on its own regardless.

== Event handlers

Set these as plain callable attributes on the client instance — none are
required, and unset ones are simply skipped:

[cols="1,3"]
|===
| Handler | Signature

| `on_deliver_sm`
| `(client, pdu: DeliverSm) -> None` — inbound message or delivery receipt.
  Check `pdu.esm_class & 0x04` to tell a delivery receipt from a
  mobile-originated message. The client auto-acknowledges with
  `deliver_sm_resp` before this handler runs.

| `on_data_sm`
| `(client, pdu: DataSm) -> None` — SMSC-initiated `data_sm`. When this
  handler is set, the client auto-acknowledges with `data_sm_resp` before it
  runs. Without a handler, the client refuses the `data_sm` with
  `data_sm_resp` `ESME_RINVCMDID`, so the SMSC knows it was not delivered. Read the
  content with `pdu.get_message_text()` or `pdu.get_message_payload()`.

| `on_connection_lost`
| `(client, error: Exception) -> None` — the socket dropped, expectedly or not.

| `on_bind_success`
| `(client, bind_type: BindType) -> None` — fired right after a bind completes.

| `on_unbind`
| `(client) -> None` — fired after `unbind()` completes, or after the
  server sends an unbind request that the client auto-acknowledges.
|===

An exception raised inside a handler is caught and logged
(`logger.exception`); it never propagates back into the client's internals.

`enquire_link` and `unbind` requests initiated *by the server* are handled
automatically: the client responds and, for unbind, updates its own bound
state and fires `on_unbind` — no handler needs to be set for that to work.
